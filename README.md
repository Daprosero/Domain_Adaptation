# CREDA and MIL-CREDA: Rényi-entropy domain adaptation

This repository holds two methods:

- **MIL-CREDA**, multiple-instance domain adaptation for attention deficit diagnosis from EEG: each subject is a bag of windows with one label, phase 1 trains an attention-weighted bag model on the source, and phase 2 adapts it to an unlabeled target with a class-conditional global alignment (matrix-based Rényi entropy) and a subject-conditioned local alignment. It is the code of the manuscript *Multiple-Instance Domain Adaptation for Attention Deficit Diagnosis*.
- **CREDA**, the image domain adaptation method of the earlier article (see [CREDA](#creda-conditional-rényi-α-entropy-domain-adaptation) below).

### Data

The real-data experiments use *EEG data for ADHD / Control children* (Nasrabadi et al., IEEE DataPort, 2020, https://doi.org/10.21227/rzfh-zn36), 121 children (61 ADHD, 60 control), 19 channels at 128 Hz. The notebooks read it from the public Kaggle dataset [`daprosero/mi-tdah-dataset`](https://www.kaggle.com/datasets/daprosero/mi-tdah-dataset) (CC0), folder `MI_TDAH_Dataset/TDAH/ieee`:

- in a Kaggle notebook, attach that dataset and it is read from `/kaggle/input`;
- anywhere else (Colab, a laptop), `repro.ieee_root()` downloads only the 121 `.mat` files listed in `MIL-CREDA-EEG/Manifests/ieee_files.json` (about 33 MB) with `kagglehub`; set `IEEE_ROOT` to use a copy you already have.

Preprocessing runs on the fly in every run (50 Hz notch, 4 s windows with 50 % overlap, at most 60 windows per subject, 1–45 Hz band-pass, average reference), so no preprocessed copy is stored. The synthetic data are generated by `eeg_sim.py` from fixed seeds.

## Reproduce the paper

Every data figure and table of the paper is rebuilt by **`MIL-CREDA-EEG/Notebooks/Results_Paper.ipynb`** from the summaries stored in `MIL-CREDA-EEG/Results/paper/`. It trains nothing, runs in about a minute on any CPU, and checks the 282 numbers the paper states (tables and text) against those summaries; `Results/paper/paper_checks.csv` lists them.

To regenerate a summary instead of using the stored one, run the stage notebook that produced it. Each one calls the entrypoints the paper's runs used, with the same parameters, and ends by comparing its numbers with the paper. Retrained numbers can differ slightly from the paper: the runs were made on Kaggle's x86 CPUs, and phase 1 and the simulator are not bit-identical across platforms (the ADHD picks reproduced exactly on an Apple M2; some synthetic picks moved by a few hundredths).

Stages read what earlier stages stored (bases, picks, condensed per-trial outputs) from the tracked folders, so any one of them can be rerun alone; to chain regenerated inputs instead, point it at the earlier stage's regenerated folder (for example `stage01_bases.bases_dir(regenerated=True)`).

### Splitting a stage over several Kaggle accounts

The paper's stages ran as many Kaggle CPU notebooks spread over several accounts (12-hour sessions and a weekly quota per account). Here each stage is one notebook, and its first cell sets how much of it this session runs:

```python
SPLIT = None     # run every unit of the stage in this session
SPLIT = (k, n)   # run portion k of n (0 <= k < n): units k, k+n, k+2n, ...
```

1. Pick `n` from the cost above and the sessions you have, for example `n = 8` for `04_ADHD_Pool` (about 11 CPU hours per portion).
2. Run the notebook `n` times, in any accounts, with `SPLIT = (0, n)`, …, `(n-1, n)`. On Kaggle, attach `daprosero/mi-tdah-dataset`, select a CPU session and save the version so the outputs are kept.
3. Copy each session's raw output folder (`MIL-CREDA-EEG/Results/paper/<stage>/raw/`; `runs/` for stage 06) into one checkout and run the notebook once more with the merge and render cells only: `merge` joins the portions, names the units still missing, and writes the stage summary; then `render` and the comparison cells show the tables, figures and paper numbers.

Every unit runs with its own fixed seeds, so a portion gives the same result whichever session runs it, and `repro.portion` is the one rule all stages use. To automate the sessions, a submission script only has to create one Kaggle notebook version per `k` with `SPLIT = (k, n)` (for example with the `kaggle kernels push` CLI and a `kernel-metadata.json` that attaches the dataset), then download each version's output folder into `Results/paper/<stage>/raw/`. Raw outputs are regenerated, never committed: `Results/paper/.gitignore` keeps them out (the ADHD pool alone writes about 1.9 GB). Every stored file stays below 50 MB, so the repository needs no Git LFS.

### Archived branches

The development branches `ieee-pool`, `ieee-pool-slim` and `pool-aggregation` were folded into `main` and deleted; their tips stay available as the tags `archive/ieee-pool`, `archive/ieee-pool-slim` and `archive/pool-aggregation`. The phase-1 bases and picks in `MIL-CREDA-EEG/Manifests/` are the ones of `archive/ieee-pool-slim`, which the paper's runs used.

The earlier BALLADEER campaigns (protocols v58–v64) are not part of the paper and were removed with their data, notebooks, pilots and job folders. Some modules of the paper's code path keep the name of the protocol version that introduced them (`v63_setup` holds MIL-CREDA's phase-2 rules, `v63_filters` the band-pass); they read no BALLADEER data.

# CREDA: Conditional Rényi α-Entropy Domain Adaptation

This repository contains an implementation of **CREDA** (Conditional Rényi α-Entropy Domain Adaptation), a deep-learning approach for unsupervised image domain adaptation. It combines source-domain classification with class-conditional feature alignment based on Rényi quadratic entropy and confidence-weighted target pseudo-labels.

The implementation follows the article: [Conditional Domain Adaptation with α-Rényi Entropy Regularization and Noise-Aware Label Weighting](https://www.mdpi.com/2227-7390/13/16/2602).

## Included components

- CREDA model and loss implementations in `src/CREDA/models.py`.
- Training utilities for CREDA and comparison methods in `src/CREDA/training_pipeline.py`.
- Result-generation notebooks under `CREDA/Notebooks/` and stored model/result artifacts under `CREDA/`.
- One toyset training tutorial per method (see below).

## Toyset tutorials: how to train CREDA and MIL-CREDA

Each method has exactly one toyset notebook. It is a complete, readable training example: data, model, loss, optimizer, training loops, evaluation and plots, on the three toyset families (`lunas`, `toroide`, `rollo`) with a single architecture, an MLP with BatchNorm (fixed, not a choice).

| Method | Notebook | What you choose |
|--------|----------|-----------------|
| CREDA | `CREDA/Notebooks/Toyset.ipynb` | `VERSION = "v2"` (default, the current two-phase protocol) or `"v01"` (the single joint training of the previous publication). Each version is one dictionary in an `if/else`. |
| MIL-CREDA | `MIL-CREDA/Notebooks/Toyset.ipynb` | The budget cell; bags, the adapted arm and the declared hyperparameters come from `MIL_CREDA_Benchmark`. |

### Run it

1. Install the dependencies from `requirements.txt` in a virtual environment.
2. Start Jupyter as usual, either from the repository root (`jupyter lab`, then open the notebook) or from the notebook's folder (`cd CREDA/Notebooks && jupyter lab Toyset.ipynb`).
3. Run all cells. The kernel starts in the notebook's folder and the first cell resolves the repository root from there, so no install of `src/` is needed.

Both notebooks train on CPU, download nothing and write no separate result files; models, histories and figures stay in memory. The notebooks are saved with executed outputs. Each starts with one input-data figure: three 3D panels (one per toyset), with source (`x`) and target (`o`) overlaid on the same axes. Source points are coloured by class and target points stay grey, without using target labels. Outputs also include an adaptation GIF and a confidence-`w` animation for each family (six GIFs per method), alongside the static summaries. CREDA reads confidence on points; MIL-CREDA reads it on bag posteriors. Adaptation frames come from real training epochs; the confidence paths are constructed sweeps, not training time.

Rendering controls do not change training: CREDA's `FRAMES` selects captured epochs and `WALK_STEPS` sets the confidence-walk resolution; MIL-CREDA's `BARRIDOS_W` sets its confidence-walk resolution.

### Budgets are didactic, not published results

The defaults are short so the notebooks finish quickly. They are not tuned and they are not the image benchmarks or the stored runs under `*/Results/`; the accuracies a notebook prints belong to that run only.

| Notebook | Defaults (one seed) |
|----------|---------------------|
| CREDA, `v2` | `source_epochs=60` (ceiling, early stop with `source_patience=15`), then `adaptation_epochs=20` |
| CREDA, `v01` | `epochs=60` of joint training |
| MIL-CREDA | `TRIALS = 6` phase-2 configurations per family (the paper draws 100), phase 2 at the paper's 100 epochs |

To change the CREDA budget, set `ADJUSTMENTS` (for example `{"source_epochs": 3, "adaptation_epochs": 2}`); for MIL-CREDA, edit the budget cell.

`MIL-CREDA/AGREED-TOYSET.md` is kept as the historical record of the earlier toyset experiment; the tutorials above replace it as the entrypoint.

### Legacy toyset experiments were removed

The earlier toyset benchmark code is gone, not hidden: its experiment runners, hyperparameter searches, sweeps, ablations, contamination and oracle experiments, result-file I/O and renderers (`CREDA.toy_plots`, `MIL_CREDA_Benchmark.toy_tables`, and the corresponding functions of `CREDA.toy_experiment` and `MIL_CREDA_Benchmark.toy_run`). Nothing in the repository regenerates the toyset artefacts stored under `CREDA/Results/tesis/toyset/` or `MIL-CREDA/Results/Toyset/`; they remain only as a historical record. The publication notebooks `CREDA/Notebooks/{Results,Plots,Tables}_Generator.ipynb` and their source modules are unchanged.
